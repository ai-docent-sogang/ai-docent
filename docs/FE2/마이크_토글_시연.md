# 마이크 토글 시연 (2026-11-24)

회의 근거: 11/18 음성 UX 결정(뮤트/언뮤트). 담당: FE2 윤재호.

## 동작

- Live 연결 성공: 기존 handsfree 음성 대화를 유지한다. `Microphone on`에서 한 번 누르면 `Microphone off`, 다시 누르면 입력 재개. 뮤트 중에도 도슨트 답변과 카메라는 계속 작동한다.
- Live 연결 실패: `/api/turn` 녹음 경로로 전환하며 마이크는 꺼진 상태로 시작한다. 한 번 탭해 질문하고, 다시 탭해 음소거와 전송을 한다. 이 경로는 발화 끝 자동 감지가 없는 턴 단위 대화다.
- 뮤트 버튼의 `aria-pressed=true`는 음소거 켜짐을 뜻한다. 연결·재연결 중에는 버튼을 비활성화하며, iOS의 오디오 재개가 필요하면 `Tap to resume` 동작을 유지한다.
- 전송 준비 중 연속 탭은 새 녹음을 만들지 않는다. 관람 종료 시 진행 중 녹음은 전송하지 않고 폐기한다.
- Live는 기존 전송 차단 로직(음소거 시 무음 600ms 후 실제 PCM 전송 중지)을 사용한다. 녹음 경로에서는 마이크 트랙의 `enabled`도 끈다. 브라우저의 장치 권한 해제와는 다르다.

## 팀원이 같은 수정본 실행하기

```bash
git fetch origin
git switch --track origin/jaeho/mic-toggle
uv sync
```

이미 해당 브랜치를 받았다면 `git switch jaeho/mic-toggle` 후 `git pull --ff-only`를 실행한다.

저장소 최상위 `.env`에 팀에서 사용하는 `GEMINI_API_KEY`, 요청-응답용 `GEMINI_MODEL`과 필요한 `LIVE_MODEL` 설정을 넣는다. 키를 코드나 GitHub에 올리지 않는다. 기존에 설정된 서버라면 그대로 사용한다.

```bash
uv run uvicorn server.app:app --host 0.0.0.0 --port 8000
```

노트북에서는 `http://localhost:8000`으로 연다. 휴대폰 공유 시에는 HTTPS 주소가 필요하다. README의 기존 터널 실행 방법으로 8000번 서버를 공유하고, 출력된 주소를 팀원에게 전달한다. 서버와 터널이 실행 중일 때만 사용할 수 있다. GitHub 저장소 주소 자체는 앱 실행 주소가 아니다.

## 검증

```bash
node tests/test_app_mic_toggle.mjs
node tests/test_live_conversation.mjs
node tests/test_live_mic.mjs
node tests/test_live_player.mjs
```

위 자동 검사는 서버·Gemini 없이 실행된다. UI 이벤트→녹음 트랙 제어→전송, 빠른 연속 탭, 종료 시 폐기, Live 토글·재연결 상태, 기존 PCM 전송 차단을 확인한다.

실기기 검증은 별도로 필요하다:

1. 이어폰을 연결하고 관람 시작. Live 연결 성공 후 탭하여 마이크를 끈다.
2. 주변에서 말해도 새 질문이 전달되지 않는지 확인한다. 마이크를 다시 켜 질문하고 답변을 확인한다.
3. Live 사용 불가 환경에서 탭 녹음→다시 탭하여 전송을 확인한다. 손을 떼는 것만으로 전송되지 않아야 한다.
4. 질문 전송 중 빠르게 여러 번 눌러도 중복 전송되지 않아야 한다.
5. 녹음 중 END VISIT으로 종료하면 미완성 질문이 전달되지 않아야 한다.
6. iPhone에서 화면 복귀·재연결·Tap to resume 후 상태 표시를 확인한다.

현재 자동 검사 통과는 실제 Gemini 응답, 현장 소음, iPhone 실기기, 외부 공유 서버 배포 검증을 대신하지 않는다.
