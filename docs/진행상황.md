# 진행 상황

팀원과 AI 코딩 도구(Claude Code 등)가 함께 보는 현황판이다. 작업을 마치면 맨 위 "최근 기록"에 한 줄을 추가하고, 아래 표의 상태를 고친다. 일정과 목표는 [개발계획서](개발계획서.md) 8장을 따른다.

- 2026-11-11 · 도혁 · 아이폰에서 Live 시험 **L01~L10 전부 통과**. 마이크 48000 Hz → 16kHz 변환 동작, 말 끝난 뒤 첫 소리 **1,457 ms**(`/api/ask` 7,945 ms의 약 1/5.5), 2분 이상 공백 뒤 재연결 성공·대화 내용 유지, 엉뚱한 작품 질문은 걸러냄. 재생 Hz는 기록 못 함 (`docs/FE1_아이폰_시험.md`, `docs/FE1_Live_검토.md`)
- 2026-11-11 · 도혁 · **아이폰 Safari에서 Live 음성 왕복 확인.** L03(생 PCM 24kHz 재생)·L04(받아쓰기) 통과 — Live 전환의 전제가 성립한다. 실기기에서 중계 결함 2개가 드러나 고침: ① `session.receive()`가 한 턴 뒤 끝나는데 한 번만 돌려서 두 번째 질문부터 무응답(턴마다 다시 호출, 누르고 말하기용 수동 VAD로 전환) ② 질문 사이 2분이면 Gemini가 `1008 client inactivity`로 세션 종료 → 폰에 1006으로 보임(재개 핸들로 자동 재연결, 대화 내용 유지 확인). 맥 측정: 3턴 연속 600~1,100ms, 170초 공백 뒤 재연결 후 630ms. 아이폰 L09 재확인은 남음 (`tools/live_relay_spike.py`, `static/live_test.js`, `docs/FE1_Live_검토.md`)
- 2026-11-11 · 도혁 · Live 음성 요금 확인(공식 요금표). 측정값 기준 한 번 질문당 Live 약 6원 vs 요청-응답 약 3.5원으로 **1.7배**. 시연 30명×10번이면 차이가 700원 정도여서 금액은 전환을 막을 이유가 아니다 (`docs/FE1_Live_검토.md`)
- 2026-11-11 · 도혁 · 아이폰용 Live 음성 시험 페이지 작성(`/live`). AudioWorklet으로 마이크를 16kHz PCM으로 실시간 전송, 받은 24kHz 생 PCM을 끊김 없이 이어 재생. 변환·스케줄링은 모의 테스트로 검증(48/44.1/32/16kHz에서 누적 오차 없음, 조각이 앞 조각 끝에 정확히 붙음). **아이폰 실기기 시험은 사용자 대기**(`docs/FE1_아이폰_시험.md` L01~L10) (`static/live_test.html`, `static/live_mic_worklet.js`, `static/live_player.js`)
- 2026-11-11 · 도혁 · Live API 전환 검토 중 코드로 확인 가능한 부분 확인. Live에 **음성**을 넣어도 받아쓰기 정확하고 `key_facts`로 답한다(엉뚱한 작품 질문도 걸러냄). 폰→우리 서버→Gemini WebSocket 중계 스파이크로 **말 끝난 뒤 첫 음성 950ms** 측정 — `/api/ask` 7.9초의 1/8. 아이폰 AudioWorklet 마이크 전송·생 PCM 재생·세션 15분 제한 처리는 미확인·미구현 (`docs/FE1_Live_검토.md`, `tools/probe_live_audio.py`, `tools/live_relay_spike.py`)
