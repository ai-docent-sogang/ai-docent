# ADR-001: 같은 사실은 한곳에만 두고, 나머지는 받아 쓴다

**상태:** 제안 (FE1 작성, 팀 확인 전)
**날짜:** 2026-11-18
**정해야 할 사람:** 팀장(FE1) · 화면 FE2 재호 · 콘텐츠 FE3 예원 · 형식 BE1 인우 · 인식 BE2 준환
**다루는 범위:** 작품·비교 정보, 설정 숫자, 라벨 목록처럼 **여러 곳에서 쓰는 사실**을 어디에 두나

---

## 1. 무슨 일이 있었나

2026-11-18 하루에 **같은 종류의 버그가 네 번** 났다. 네 번 다 원인이 하나다. **같은 사실이 두 곳에 적혀 있었고, 한쪽만 바뀌었다.**

| # | 무엇이 두 곳에 있었나 | 어긋나서 보인 증상 | 알아챈 방법 |
| --- | --- | --- | --- |
| 1 | 비교쌍 정보 — `data/comparisons.csv`(원본)와 `static/app.js`의 손으로 베낀 목록 | FE3가 7→20점으로 늘리자 화면 목록은 7개에 머물렀다. **14개 비교가 요약에서 "NO COMPARISON USED"로 보였다.** 내가 아침에 더한 ID 하나는 이름이 바뀌어 죽은 ID가 됐다 | 관람 기록을 검수하다 우연히 |
| 2 | 비교쌍 ID — CSV와 `tests/test_live_session_lifetime.py`에 박아 둔 값 | FE3가 `C_KHD_HOKUSAI_MANGA`를 `..._SUMO`로 바꾸자 **코드는 멀쩡한데 시험만 깨졌다** | main을 가져오다 |
| 3 | 사진 가로 크기 — `static/app.js`(1100)와 `static/live_conversation.js`(768) | BE2 요청으로 1100으로 올렸는데 **주 경로인 Live는 768에 머물렀다.** 요청이 반영되지 않은 채로 며칠 갈 수 있었다 | 전 과정 문서를 쓰려고 숫자를 확인하다 |
| 4 | 비교 후보 **순서** — BE1의 `comparison_block`과 FE1의 `ranked_comparison_ids`가 따로 계산 | 프로필에 `region`만 오면 글은 스모가 1번인데 ID 목록은 브뤼헐이 1번. **모델이 스모를 말하면서 브뤼헐을 기록한다** | `api.md` 점검에서 |
| 5 | 메시지 칸 이름 — 서버가 보내는 칸과 `live_conversation.js`가 골라 받는 칸 | 서버가 새로 보내기 시작한 `artist`·`foreign_*`가 **조용히 버려졌다.** 시험 세 벌이 다 통과하는데 화면은 고장 | 화면을 실제로 띄워 보고 |

**공통점이 중요하다.**

- **다섯 번 다 조용히 틀렸다.** 서버가 죽지도, 시험이 깨지지도 않았다(2번만 예외). 요약에서 비교가 사라지거나, 요청이 반영되지 않거나, 기록이 틀렸다.
- **네 번은 우연히 발견했다.** 다른 일을 하다 숫자를 확인하면서 찾았다. 아무도 안 봤으면 12/1 시연에서 처음 보였을 것이다.
- **고치는 데는 오래 걸리지 않았다.** 문제는 고치는 비용이 아니라 **틀린 걸 모른다는 것**이다.

---

## 2. 결정

**같은 사실은 한곳에만 둔다. 나머지는 그 한곳에서 받아 쓴다.** 손으로 베낀 사본을 만들지 않는다.

적용한 것(11/18 완료):

| 사실 | 단일 출처 | 받아 쓰는 쪽 |
| --- | --- | --- |
| 작품·비교쌍 정보 | `data/*.csv` → 서버가 읽음 | 화면은 서버가 보내는 `artwork`·`comparison` 메시지로 받는다. 베낀 목록 2개를 지웠다 |
| 사진 간격·크기·화질 | `static/live_conversation.js`의 `FRAME_*` | `static/app.js`가 `import`해서 쓴다 |
| 비교 후보 순서 | BE1의 `home_of`·`rank_comparisons` | FE1이 같은 함수를 부른다(따로 계산하지 않는다) |
| 시험이 기대하는 ID | CSV | 시험이 CSV에서 읽는다(박아 두지 않는다) |
| 메시지 칸 | 서버가 보내는 것 | 폰은 **골라내지 않고 그대로 넘긴다** |

## 3. 생각해 본 길들

### 가. 손으로 맞춘다 (지금까지 해 온 것)

| 항목 | 평가 |
| --- | --- |
| 복잡도 | 낮음 |
| 비용 | 한 번에 10~20분. **바뀔 때마다** |
| 들어맞는 범위 | 자료가 안 바뀌면 괜찮다 |
| 팀 숙련도 | 설명이 필요 없다 |

**좋은 점**: 지금 당장 제일 빠르다. 구조를 안 건드린다.
**나쁜 점**: **오늘 두 번 했고 두 번 다 몇 시간 안에 또 어긋났다.** 12/1까지 FE3가 콘텐츠를 더 늘릴 것이 확실하다. 그리고 어긋나도 아무도 모른다.

### 나. 단일 출처 + 받아 쓰기 (고른 것)

| 항목 | 평가 |
| --- | --- |
| 복잡도 | 중간. 서버가 보낼 칸을 늘리고, 화면이 받아 쓰게 바꾼다 |
| 비용 | 비교쌍은 약 2시간(11/18에 했다). 설정 숫자는 10분 |
| 들어맞는 범위 | 자료가 늘어나도 어긋날 수 없다 |
| 팀 숙련도 | 평범한 방식이다. 역할 가이드에 이미 비슷한 합의가 있다 |

**좋은 점**: 어긋남이 **구조적으로 불가능**해진다. 화면 코드가 짧아진다(목록 두 개가 사라졌다). FE3가 CSV만 고치면 끝난다.
**나쁜 점**: 서버가 보내는 양이 조금 늘어난다(비교 하나에 네 칸). 메시지 형식이 바뀌므로 BE1 합의가 필요하다. 그리고 **이 방식도 안전하지 않다** — 아래 5번을 보라.

### 다. 자료에서 코드를 만들어 낸다 (생성)

CSV에서 화면용 JS 파일을 빌드 때 만들어 낸다.

| 항목 | 평가 |
| --- | --- |
| 복잡도 | 높음. 빌드 단계가 생긴다 |
| 비용 | 반나절 이상 |
| 들어맞는 범위 | 어긋남은 막힌다 |
| 팀 숙련도 | **이 저장소에 빌드 단계가 없다.** 지금 `static/`은 그대로 내려간다 |

**버린 이유**: 12/1까지 2주다. 빌드 단계를 새로 들이면 팀원 다섯이 모두 그것을 배워야 하고, 멘토도 압축 파일을 풀어 `uv sync` 한 번으로 켤 수 있어야 한다. 효과는 (나)와 같은데 비용이 몇 배다.

### 라. 아무것도 안 한다

12/1까지 콘텐츠가 더 안 바뀐다고 믿는 것이다. **오늘 하루에 네 번 났으므로 근거가 없다.**

---

## 4. 맞바꾼 것

**(나)를 골랐다.** 근거는 하나다. **(가)를 오늘 두 번 했고 두 번 다 실패했다.** 같은 방법을 세 번째로 시도할 이유가 없다.

(다)가 더 튼튼하지만 **지금 들일 수 없다.** 빌드 단계는 12/1 뒤에 다시 볼 일이다.

**(나)를 고르면서 받아들인 것**: 메시지가 조금 커진다. 비교 하나에 네 칸이 더 붙는데, 한 관람에 비교는 몇 번뿐이라 비용에 보이지 않는다(실측에서 관람 토큰의 대부분은 지시문 재전송이고 사진은 5%였다).

## 5. 그래서 무엇이 쉬워지고 무엇이 어려워지나

**쉬워진 것**
- FE3가 CSV만 고치면 화면까지 따라온다. 요약에서 비교가 사라지는 일이 없다.
- 설정 숫자를 한 곳에서 바꾸면 두 경로가 같이 바뀐다.
- 화면 코드가 짧아졌다(목록 두 개, 약 25줄).

**어려워진 것 — 솔직히 적는다**
- **단일 출처로 바꾸는 과정에서 새 버그가 생겼다.** 서버가 새 칸을 보내기 시작했는데 `live_conversation.js`가 칸 이름을 골라 받고 있어서 **조용히 버렸다.** 시험 세 벌이 다 통과했고 화면만 고장 나 있었다. 그러니까 **"단일 출처"는 전달 통로가 투명할 때만 성립한다.** 중간에 칸을 골라내는 코드가 있으면 거기서 다시 어긋난다.
- 메시지 형식을 바꾸므로 BE1과 합의해야 한다. `docs/api.md`는 BE1 담당이다.

**다시 봐야 할 것**
- `docs/api.md`는 여전히 코드의 숫자를 **글로 베껴 적는다.** 오늘도 내가 단일 출처를 1100으로 바꾼 뒤 `api.md`가 한 숫자 뒤처졌다(고쳤다). 문서는 생성하지 않는 한 사본이다. 대신 **문서가 어느 파일을 단일 출처로 삼는지 적어 두기로** 했다.
- 아직 남은 사본이 있다. 아래.

## 6. 아직 남아 있는 사본

점검해서 찾은 것이다. 고치지 않았다.

| 사실 | 적혀 있는 곳 | 어긋나면 |
| --- | --- | --- |
| 마이크 샘플레이트 16000 | `static/audio.js:59`, `static/live_mic_worklet.js:15`, `server/live.py:179,293,774` | 소리가 깨지거나 Gemini가 알아듣지 못한다. 프로토콜 상수라 바뀔 일이 거의 없다 |
| 재생 샘플레이트 24000 | `static/live_player.js:16`, `static/live_test.js:206` | 같음 |
| 질문 라벨 목록 | `tools/classify_questions.py`의 `LABELS`, `data/eval/question_labels_2026-11-17.csv`, FE3의 평가 질문 `label` 칸 | 분류기와 사람 라벨이 다른 체계가 된다. **FE3와 정해야 한다** |
| 환경 변수 기본값 | `server/live.py`, `.env.example`, `README.md`, `docs/api.md` | 문서대로 설정해도 다르게 동작한다. 오늘 한 번 맞췄다 |

**`server/live.py`에 `python -m server.live --env-table` 같은 것을 두어 README·`.env.example`·`api.md`의 표를 찍어 내게 하면** 마지막 줄이 사라진다. 11/18 구조 점검에서도 같은 제안이 나왔다. 12/1 뒤 일로 둔다.

## 8. 이 결정에서 배운 것 하나

**"시험이 통과한다"가 "동작한다"가 아니었다.** 5번 버그는 시험 세 벌(서버 139건, 기록 53건, 화면 19가지)이 전부 통과하는데 화면이 고장 나 있었다. 서버가 보내는 것을 보는 시험과 화면이 그리는 것을 보는 시험이 따로 있었고, **그 사이를 보는 것이 없었다.**

그래서 그 뒤로는 **서버 쪽과 화면 쪽을 따로 확인하고**, 화면은 실제 브라우저에 가짜 WebSocket을 끼워 눈으로 확인했다. `static/app.js`를 띄우는 자동 시험이 없다는 것이 지금 가장 큰 빈칸이다(7번).
