# 관람 기록 설계 — Live handsfree 흐름에서 무엇을 남기나 (11/18 초안)

작성: FE1, 11/18. **11/18 갱신: 기록 모듈을 만들었다**(`server/visit_log.py`, 시험 `tests/test_visit_log.py` 39건). 아직 `server/live.py`에 연결하지 않았다. 근거: [근거 조사](<AI 도슨트 관람 분석 측정 계획 근거 조사_ 국립중앙박물관 조선회화 전시의 질문 로그 기반 콘텐츠 공백 진단.md>), [측정 계획](FE1_관람분석_측정계획.md). 검토 전 초안이다. 코드는 아직 없다.

## 왜 다시 설계하나

측정 계획(11/14~16)은 "관람객이 앱에서 작품 화면을 열고 닫는다"를 전제로 `artwork_open`·`artwork_close`를 세웠다. 11/18에 화면이 버튼 없는 Live 대화(handsfree)로 바뀌면서 그 사건이 사라졌다. 이제 작품은 **Live가 카메라 사진을 보고 함수(`report_current_artwork`)로 알려 줄 때** 정해지고, 질문은 버튼이 아니라 **자동 음성 감지가 나눈 턴**이다. 그래서 기록 단위를 새 흐름에 맞춘다.

11/18 아침까지는 **아무것도 저장하지 않았다**. 서버 디스크 쓰기 없음, `server/logs.py`(BE2)는 빈 자리, 세션 기억은 END VISIT이나 서버 재시작 때 사라졌다.

11/18 저녁 기준으로 **기록 모듈 `server/visit_log.py`가 생겼다**(FE1). 아래 사건 8종을 JSON Lines로 남긴다. `server/logs.py`(BE2 자리)는 비워 두었다 — 담당이 정해지면 옮기거나 합친다. **아직 `server/live.py`에 연결하지 않았으므로, 지금도 실제로 저장되는 것은 없다.**

## 남기는 것

한 줄이 사건 하나인 JSON Lines. 위치는 `logs/visits-YYYYMMDD.jsonl`(`logs/`는 이미 git 제외). 모든 줄에 `visit_id`(관람마다 새로 만드는 난수 — 서버 세션 ID와 다르다), `t`(관람 시작부터의 초, 소수 첫째 자리), `source_kind`가 붙는다.

| 사건 | 필드 | 어디서 생기나 (지금 코드) |
| --- | --- | --- |
| `visit_start` | `start_bucket`(10분 버림), `season_id`, `gallery`, `ui_lang`, `mode`(handsfree/push), `model`, `voice` | `/ws/live` 첫 메시지 처리, 설정값 |
| `artwork_identified` | `artwork_id`, `via`(function) | `report_current_artwork`가 11점 중 하나를 돌려줄 때. `unknown`은 `artwork_unknown`으로 따로 센다 |
| `question` | `artwork_id`(그때의 작품), `channel`(voice/text), `label`, `outcome`, `first_audio_ms` | 턴이 끝날 때(`remember_turn`). 라벨·결과는 아래 "정할 것" |
| `comparison` | `artwork_id`, `comparison_id`, `via`(function/transcript) | `report_comparison`, 또는 답 속 제목 대조 |
| `quality` | `issue`(`interrupted`/`reconnect`/`resumed`/`phone_idle_close` 중 하나), `kept_conversation` | 끼어들기·재연결·30초 무입력 닫힘 |
| `usage` | 입력 소리·사진·글, 출력 소리 토큰 수 | Gemini 응답의 `usage_metadata`. **지금은 아무 데도 기록하지 않는다** — 비용 최적화(3번)의 재료 |
| `visit_end` | `duration_s`(10초 단위 버림), 사건 수 합계 | END VISIT, 폰 연결 끝 |

**남기지 않는 것**: 들은 말·한 말의 글자, 소리, 사진, 서버 세션 ID, 국적·연령대(지역 선택값 포함), IP·기기 정보, 벽시계 시각(시작 버킷 외).

## 박물관에 줄 수 있는 것

1. **지금 답할 수 있음 — 콘텐츠 공백 지도**: 작품 × 질문 라벨 × 결과(`no_source` 비율). 근거 조사가 가장 강하다고 본 산출물이고, Brooklyn Museum ASK와 같은 구조다.
2. **구조만 준비됨 — 대리 지표**: 관람에서 인식된 작품과 그 순서, 작품별 질문률(질문 수 ÷ 인식된 관람 수), "Live 작품 인식 구간"(같은 작품이 처음·마지막으로 인식된 상대 시각). **이건 체류 시간이 아니다.** Live는 그 그림 이야기를 꺼낼 때만 함수를 부르므로 띄엄띄엄 찍힌다. 연속 체류를 재려면 서버가 3초마다 지나가는 사진을 따로 판정해야 한다(BE2 인식과 연결, 5번).
3. **이 기록으로 주장할 수 없음**: Serrell SRI·%DV, 실제 작품 앞 관람 시간, 동선·혼잡도. 무작위 관찰 표본·면적·위치 장비가 필요하다.

## 글자를 남기지 않는 것을 코드로 막았다

AGENTS.md의 약속은 사람이 기억해야 지켜진다. 그래서 `server/visit_log.py`가 거부하게 했다.

- 사건마다 넣을 수 있는 칸이 `ALLOWED`에 적혀 있고, 그 밖의 칸은 `FieldNotAllowed`로 거부한다. 들은 말·한 말·서버 세션 ID·국적·연령대는 **넣을 칸 자체가 없다.**
- 칸 이름이 맞아도 **64자를 넘으면 거부한다.** 받아쓰기가 실수로 섞여 들어오는 것을 막는다.
- 기록 때문에 관람이 멈추지 않는다. 폴더를 못 쓰면 한 번 알리고 조용히 꺼진다.
- 시험이 `ALLOWED`의 사건 이름과 이 문서에 적힌 이름이 같은지 검사한다. 한쪽만 바뀌면 시험이 깨진다.
