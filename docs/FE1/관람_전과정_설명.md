# 관람 한 번의 전 과정 — 무엇이 일어나고 무엇이 오가나

작성: FE1 김도혁, 2026-11-18. 멘토 전달본(버튼 없는 Live 대화) 기준.

이 문서는 **관람객이 START를 누른 순간부터 관람을 끝낼 때까지** 폰·서버·Gemini 사이에 무엇이 오가는지를 순서대로 적은 것이다. 코드를 읽지 않고도 흐름과 주고받는 값을 알 수 있게 쓴다. 형식의 정식 명세는 [`docs/api.md`](../api.md)의 `/ws/live` 절이고, 이 문서는 그것을 과정 순서로 풀어 쓴 것이다.

읽는 순서: 1장(한눈에) → 2장(과정) → 3장(오가는 값) → 4장(쓰는 기술) → 5장(한계).

---

## 1. 한눈에

```text
 [관람객]          [폰 웹앱]                 [우리 서버]                [Google Gemini]
    │          static/index.html          server/live.py              gemini-3.8-live
    │          static/app.js              WS /ws/live                 (Live API)
    │          static/live_conversation.js
    │                 │                         │                          │
  말 ──마이크──▶ 16kHz PCM ──WebSocket──▶ 그대로 중계 ──WebSocket──▶ 알아듣고 답을 만든다
    │                 │                         │                          │
  그림 ─카메라─▶ JPEG 3초마다 ──────────▶ 그대로 중계 ─────────────▶ 어느 그림인지 본다
    │                 │                         │     ◀── 함수 호출 ────────┤
    │                 │                         │   "이 그림은 KHD_SSIREUM"  │
    │                 │                    CSV에서 검증된 사실을 찾아 ──────▶ 그 사실만으로 말한다
    │                 │                         │                          │
  소리 ◀─스피커─ 24kHz PCM ◀───────────── 그대로 중계 ◀──────────────── 음성 답변
```

핵심은 셋이다.

1. **서버는 번역하지 않고 중계한다.** 소리와 사진을 Gemini로 그대로 넘기고, 답 음성을 폰으로 그대로 넘긴다. 글자로 바꾸거나 다시 만들지 않는다. 그래서 응답이 빠르다.
2. **무엇을 말할지는 서버가 가둔다.** Gemini가 "어느 그림인지" 함수로 보고하면, 서버가 `data/artworks.csv`의 **검증된 사실만** 골라 돌려준다. Gemini는 그 사실 안에서만 말한다.
3. **버튼이 없다.** 처음 한 번 START를 누른 뒤에는 말만 하면 된다. 말이 시작되고 끝나는 것은 Gemini가 소리를 듣고 판단한다.

## 2. 과정

### 2-1. 시작 (관람객이 화면을 한 번 만지는 유일한 순간)

| 순서 | 어디서 | 무엇이 |
| --- | --- | --- |
| 1 | 폰 | 관람객이 지역과 연령대를 고르고 **START EXPLORING**을 누른다 |
| 2 | 폰 | 카메라·마이크 허가를 받는다. iOS Safari는 HTTPS에서만 허가한다 |
| 3 | 폰 | 화면이 저절로 꺼지지 않게 막는다(Screen Wake Lock). 못 쓰면 "Keep the screen on" 안내를 한 번 보인다 |
| 4 | 폰 → 서버 | WebSocket `/ws/live`를 열고 첫 메시지를 보낸다 |
| 5 | 서버 | 관람 기억을 만들고, 지시문을 조립해 Gemini Live 세션을 연다 |
| 6 | 서버 → Gemini | **먼저 인사하라는 신호**를 보낸다. 관람객이 말을 걸지 않아도 도슨트가 먼저 말한다 |
| 7 | 서버 → 폰 | `ready`를 보낸다. 폰은 이때부터 소리와 사진을 계속 올린다 |
| 8 | Gemini → 폰 | 인사 음성이 나온다. 실측 **첫 소리까지 0.4~0.5초** |

첫 메시지(폰 → 서버):

```json
{"mode": "handsfree",
 "profile": {"country": "France", "age_group": "adult", "language": "en"},
 "session_id": "", "resume": false}
```

`ready`(서버 → 폰):

```json
{"type": "ready", "model": "gemini-3.8-live", "mode": "handsfree",
 "voice": "Kore", "session_id": "a1b2…"}
```

**인사 턴에는 사진을 넣지 않는다.** 인사와 사진이 같이 들어가면 Gemini가 인사 도중에 "지금 작품을 보고해야 하나"를 따지다가 그 속마음을 자막으로 흘렸다(11/18 측정에서 사진을 넣으면 3번 중 3번, 빼면 3번 중 1번). 그래서 인사가 끝날 때까지 사진을 들고 있다가 그때 한 장을 넘긴다.

### 2-2. 관람객이 그림 앞에 선다 — 작품 인식

| 순서 | 무엇이 |
| --- | --- |
| 1 | 폰이 **3초마다** 카메라 사진 한 장을 JPEG으로 올린다(가로 768px로 줄여서) |
| 2 | 서버가 그대로 Gemini에 넘긴다 |
| 3 | Gemini가 그림을 알아보면 **함수를 부른다**: `report_current_artwork(artwork_id="KHD_SSIREUM")` |
| 4 | 서버가 `data/artworks.csv`에서 그 작품의 **검증된 사실**과 **비교 후보**를 찾아 함수 결과로 돌려준다 |
| 5 | 서버가 폰에도 알린다(`artwork`). 화면에 "ARTWORK RECOGNIZED" 칩이 뜬다 |
| 6 | Gemini가 그 사실만으로 설명한다 |

**함수 값은 목록 안에서만 고를 수 있다.** 작품 ID는 11점 + `unknown`으로, 비교 ID는 검증된 20개로 **enum으로 묶어 두었다.** 그래서 Gemini가 없는 작품 ID를 지어낼 수 없다. 못 알아보면 `unknown`을 돌려주고, 서버는 "그림을 비춰 달라고 부탁하라"는 지시를 돌려준다. **이때 지금 작품을 지우지 않는다** — 잠깐 다른 곳을 비춘 경우를 작품이 바뀐 것으로 보면 안 되기 때문이다.

함수 결과(서버 → Gemini)에 들어가는 것:

| 칸 | 내용 |
| --- | --- |
| `artwork_id` | 확정된 작품 ID |
| `artwork` | 검증된 사실 묶음(`key_facts`). "이 사실만 쓰라"는 머리말이 붙는다 |
| `comparison_options` | 이 관람객에게 맞는 순서로 고른 외국 작품 비교 후보 설명 |
| `comparison_ids` | 위와 같은 순서의 비교 ID 목록. 다음 함수에 넣을 값이다 |

### 2-3. 관람객이 묻는다 — 한 번의 대화

| 순서 | 무엇이 |
| --- | --- |
| 1 | 폰이 마이크 소리를 **100ms 조각으로 끊임없이** 올린다(16kHz PCM). 버튼을 누르지 않는다 |
| 2 | Gemini가 자동 음성 감지로 말의 시작과 끝을 판단한다 |
| 3 | 받아쓴 질문이 서버를 거쳐 폰에 온다(`heard`) → 화면에 말풍선 |
| 4 | 답변 음성이 24kHz PCM으로 온다. 서버가 그대로 폰에 넘기고 폰이 이어 붙여 재생한다 |
| 5 | 답변 자막도 온다(`said`) → 화면에 말풍선 |
| 6 | 턴이 끝나면 `turn_complete` |

실측: 질문이 끝나고 **첫 답변 소리까지 1.2~2.9초**. 함수를 거치는 턴이 더 걸린다.

**말을 끊을 수 있다.** 도슨트가 말하는 중에 관람객이 말하면 Gemini가 `interrupted`를 보내고, 폰은 재생 중인 소리를 바로 멈춘다. 실측 0.30초·0.38초에 멈췄다.

**비교 작품을 쓸 때**도 함수를 부른다: `report_comparison(comparison_id="C_KHD_BRUEGEL")`. 서버는 그 비교가 **지금 작품의 검증된 비교쌍인지 확인하고**, 아니면 거절하면서 쓸 수 있는 ID 목록을 돌려준다. 통과하면 외국 작품의 제목·작가·소장처·유사점·차이점을 돌려주고, 폰에도 알려 요약 화면에 쌓는다.

### 2-4. 중간에 끊길 때

전시실에서 일어나는 일이라 따로 처리한다.

| 생기는 일 | 어떻게 하나 |
| --- | --- |
| Gemini가 연결 수명(약 10분)이 다 됐다고 예고(GoAway) | 답변 중이면 **끝까지 내보낸 뒤** 재개 핸들로 새 연결로 옮긴다 |
| 질문 사이 2분이 비어 Gemini가 닫는다 | 재개 핸들로 다시 붙는다. 앞 대화가 이어진다 |
| 폰 네트워크가 끊긴다 | 폰이 1·2·4·8·15초로 늘려 가며 **계속** 다시 붙는다. 버튼 방식으로 바꾸지 않는다 |
| 폰이 30초 동안 아무것도 안 보낸다 | 서버가 죽은 연결로 보고 닫는다(코드 4001). 폰은 5초마다 살아 있다는 신호를 보낸다 |
| 새로고침·탭이 다시 떠서 화면이 처음으로 돌아간다 | "Tap to continue your visit"가 뜨고, 누르면 **같은 관람으로** 이어 붙는다 |

재개 핸들은 마지막 종료 뒤 **2시간** 유효하다. 거듭 실패하면 핸들을 버리고 새 대화로 시작하되, 그때는 인사 대신 "다시 연결됐다"고만 말하고 **마지막으로 보던 작품의 사실을 넘겨** 이어 말하게 한다.

끊김은 폰에도 알린다(`reconnecting`). 앞 대화를 이었는지(`kept_conversation`)가 함께 와서 화면이 안내를 바꿀 수 있다.

### 2-5. 끝

관람객이 **END VISIT**을 누르거나 폰 연결이 끊어지면 끝난다. 서버는 Gemini 연결을 닫고, 재개 핸들만 2시간 시계와 함께 남긴다. **대화 내용·소리·사진은 남기지 않는다.** 폰은 요약 화면에 본 작품과 쓴 비교를 보여 준다.

## 3. 오가는 값 정리

### 3-1. 폰 → 서버

| 보내는 것 | 형식 | 언제 |
| --- | --- | --- |
| 첫 메시지 | `{"mode","profile","session_id","resume"}` | 연결 직후 1회 |
| 마이크 소리 | 바이너리, 16kHz 모노 PCM16 | 100ms마다 계속 |
| 카메라 사진 | `{"type":"frame","jpeg":"<base64>"}` | 3초마다 |
| 글 질문 | `{"type":"text","text":"…"}` | 관람객이 글로 물을 때 |
| 살아 있다는 신호 | `{"type":"ping"}` | 5초마다 |

### 3-2. 서버 → 폰

| 받는 것 | 형식 | 폰이 할 일 |
| --- | --- | --- |
| 준비됨 | `ready` + `model`·`mode`·`voice`·`session_id` | 소리·사진 올리기 시작 |
| 답변 음성 | 바이너리, 24kHz 모노 PCM16 | 이어 붙여 재생 |
| 받아쓴 질문 | `heard` + `text` | 관람객 말풍선 |
| 답변 자막 | `said` + `text` | 도슨트 말풍선 |
| 작품 확정 | `artwork` + `artwork_id`·`artwork_title`·`artist` | 칩 표시, 요약에 쌓기 |
| 비교 사용 | `comparison` + `comparison_id`·`artwork_id`·`source`·`foreign_title`·`foreign_artist`·`foreign_collection`·`foreign_url` | 요약·상세에 쌓기 |
| 말 끊김 | `interrupted` | 재생 즉시 멈춤 |
| 턴 끝 | `turn_complete` | — |
| 재연결 중 | `reconnecting` + `kept_conversation` | 안내 표시 |
| 오류 | `error` + `message` | 안내 표시 |

`artwork`·`comparison`에 보여 줄 값(작가·외국 작품 정보)을 **서버가 같이 보낸다.** 전에는 화면이 같은 정보를 손으로 베껴 뒀는데, 콘텐츠 CSV가 늘어날 때마다 어긋났다(11/18에 비교쌍이 7→20점이 되면서 14개가 요약에서 사라졌다). 서버가 보내므로 이제 어긋날 수 없다.

### 3-3. 서버 ↔ Gemini

| 방향 | 무엇 |
| --- | --- |
| 연결할 때 | 시스템 지시문(규칙 + 관람객 프로필 + 11점 목록 + 함수 사용 규칙), 함수 선언 2개, 목소리, 음성 감지 설정, 압축·재개 설정 |
| 서버 → | 16kHz PCM(그대로), JPEG(그대로), 인사 신호·글 질문(텍스트) |
| ← Gemini | 24kHz PCM 음성, 질문 받아쓰기, 답변 받아쓰기, 함수 호출, 끼어들기 신호, 턴 끝, 재개 핸들, 연결 종료 예고, 사용량 |
| 서버 → | 함수 결과(검증된 사실, 비교 후보) |

**관람객의 국적·연령은 Gemini 지시문에만 들어간다.** 기록에는 남기지 않는다.

## 4. 쓰는 기술

| 무엇 | 어디에 | 왜 |
| --- | --- | --- |
| **Gemini Live API** (`gemini-3.8-live`) | 음성 대화 전체 | 소리를 글자로 바꾸지 않고 바로 음성으로 답한다. 응답이 빠르고 말투가 자연스럽다 |
| **함수 호출(Function calling)** | 작품 인식, 비교 기록 | 모델이 말과 **별도로** 신호를 보낸다. 자막에서 글자를 찾는 방식은 모델이 표현을 바꾸면 놓친다 |
| **자동 음성 감지(VAD)** | 말의 시작·끝 판단 | 버튼을 없애는 핵심. 민감도를 낮춰(LOW) 짧은 추임새에 덜 반응하게 했다 |
| **세션 재개(Session resumption)** | 끊김 복구 | 끊겨도 같은 대화를 잇는다. 전시실에서 반드시 필요하다 |
| **컨텍스트 압축** | 긴 관람 | 음성 전용 세션의 15분 제한을 없앤다 |
| **WebSocket** | 폰↔서버, 서버↔Gemini | 양방향으로 끊임없이 흘려보내야 한다 |
| **AudioWorklet** | 폰 마이크 | 마이크 소리를 16kHz PCM 조각으로 끊어 올린다 |
| **Screen Wake Lock** | 화면 꺼짐 막기 | iOS Safari 18.4 이상. 글라스를 쓰면 폰을 보지 않는다 |
| **FastAPI / uvicorn** | 서버 | 저장소의 기존 스택 |
| **콘텐츠 CSV** | 작품 사실, 비교쌍 | 출처·확인일·검증 상태를 적은 자료만 쓴다. 모델이 사실을 지어내지 못하게 하는 잠금 |

### 설정으로 바꿀 수 있는 것

| 환경 변수 | 기본값 | 무엇 |
| --- | --- | --- |
| `LIVE_MODEL` | `gemini-3.8-live` | 음성 모델 |
| `LIVE_VOICE` | `Kore` | 도슨트 목소리 |
| `LIVE_FRAME_POLICY` | `every` | `on_speech`로 두면 사진을 말할 때만 Gemini에 넘긴다 |
| `LIVE_START_SENSITIVITY` | `LOW` | 말의 시작을 얼마나 민감하게 잡나 |
| `LIVE_SILENCE_MS` | `700` | 이만큼 조용하면 말이 끝난 것으로 본다 |
| `LIVE_PREFIX_MS` | `300` | 말로 인정하기까지 필요한 말소리 길이 |
| `LIVE_PHONE_IDLE_S` | `30` | 폰이 이만큼 조용하면 죽은 연결로 본다 |

**틀린 값을 적어도 서버는 켜진다.** 경고를 한 줄 찍고 기본값으로 간다. 켤 때 지금 적용된 값을 한 줄 찍는다.

```
[live] model=gemini-3.8-live voice=Kore frame_policy=every start=LOW silence=700ms prefix=300ms idle=30s
```

### 개인정보를 어떻게 다루나

- 소리·사진·대화 내용은 **처리에만 쓰고 저장하지 않는다.** 세션 기억은 관람이 끝나면 사라진다.
- 관람 기록(이용 통계)은 **기본값이 꺼짐**이고, 켜도 **글자·소리·사진을 남길 칸이 없다.** 코드가 거부한다.
- API 키는 `.env`에만 둔다. 클라이언트 코드에 넣지 않는다.

| 한계 | 상태 |
