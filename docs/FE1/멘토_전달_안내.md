# 멘토 전달 안내 — 버튼 없는 Live 도슨트 (11/18)

작성: FE1 김도혁(팀장). 이 버전은 관람객이 버튼을 누르지 않고 도슨트와 말로 대화하는 방식입니다. 처음에 한 번 시작 버튼을 누르면, 그 뒤로는 폰 화면을 보지 않아도 됩니다.

## 1. 실행

저장소 최상위 폴더에서 실행합니다.

```bash
uv sync
cp .env.example .env
```

`.env`에 **본인의 Gemini API 키**(`GEMINI_API_KEY`)와 요청-응답용 모델(`GEMINI_MODEL`, 예: `gemini-3.8-flash`)을 적습니다. Live 모델은 따로 적지 않으면 `gemini-3.8-live`를 씁니다. 키는 `.env`에만 두고 커밋하지 않습니다.

```bash
uv run uvicorn server.app:app --host 0.0.0.0 --port 8000
cloudflared tunnel --url http://localhost:8000     # 다른 터미널. 아이폰 Safari는 HTTPS에서만 카메라·마이크를 허용합니다
```

출력된 `https://….trycloudflare.com` 주소를 폰 Safari에서 엽니다. 지역·연령대를 고르고 **START EXPLORING**을 누른 뒤 카메라·마이크를 허용하면 도슨트가 먼저 인사합니다.

설정은 서버 환경 변수로 바꿉니다(목록은 [README](../../README.md) "Live 설정", 형식은 [API 약속](../api.md) `/ws/live` 절).

## 2. 사용 조건

- **폰을 잠그지 마세요.** 화면 자동 꺼짐은 막지만(Wake Lock, iOS Safari 18.4 이상), 전원 버튼으로 잠그면 웹페이지가 멈춥니다. iOS가 정한 제한이라 웹으로는 피할 수 없습니다. 20초 잠갔다 푼 실기기 시험에서는 연결이 그대로 유지됐고, 더 오래 잠그면 "Reconnecting…" 뒤 같은 대화로 다시 붙습니다(서버는 30초 동안 폰에서 아무것도 오지 않으면 연결을 닫습니다).
- **이어폰을 권합니다.** 실기기 스피커 시험에서 도슨트가 자기 목소리 때문에 말을 끊는 일은 없었지만, 전시실 소음과 다른 관람객을 생각하면 이어폰이 낫습니다.
- **마이크와 카메라가 계속 열려 있습니다.** 소리는 계속, 사진은 3초마다 서버를 거쳐 Gemini로 갑니다. 저장하지는 않습니다. 다만 다른 관람객의 말소리나 모습이 담길 수 있어 박물관과 협의 중입니다.
- 큰 버튼은 음소거 토글입니다. 다른 사람과 이야기할 때 눌러 두세요.

## 3. 스마트글라스에 붙이기

서버는 바꾸지 않아도 됩니다. 글라스 쪽이 폰 웹과 같은 형식으로 `/ws/live`에 붙으면 됩니다. 조사 결과는 [스마트글라스 연동 조사](스마트글라스_연동_조사.md)에 있습니다.

**가. 폰 웹 + 글라스를 블루투스 이어폰·마이크로 쓰기 (코드 변경 없음)**
지금 버전 그대로 동작합니다. 폰 카메라로 작품을 비추고, 소리는 글라스로 듣고 말합니다. 폰 화면은 켜 둔 채 손에 들거나 목에 걸어야 합니다.

**나. 글라스 SDK로 동반 앱을 만들어 직접 붙이기 (화면 꺼진 채로 동작하는 유일한 방법)**
카메라·마이크를 개발자에게 여는 상용 글라스(Meta DAT, Mentra, Android XR, Brilliant)는 조사 범위에서 모두 **폰 동반 앱이 블루투스로 입출력을 받는 구조**였습니다. 동반 앱이 할 일은 폰 웹(`static/live_conversation.js`)과 같습니다.

| 보내기 | 받기 |
| --- | --- |
| 연결 직후 `{"mode":"handsfree","session_id":"<POST /api/session>","profile":{...}}` | `ready` |
| 마이크를 16kHz 모노 PCM16으로 **계속** (Meta 글라스 마이크는 8kHz로 들어온다는 문서가 있어 16kHz로 올려 보내야 합니다) | 24kHz 모노 PCM16 → 재생 |
| 3초마다 `{"type":"frame","jpeg":"<base64, 가로 768px 이하>"}` | `said`/`heard` 자막, `artwork`, `comparison` |
| 5초마다 `{"type":"ping"}` | `interrupted` → **재생을 즉시 멈춤** |
| 끊기면 같은 `session_id`로 다시 붙으며 `"resume": true` | `resumed: true`면 대화가 이어짐 |

글라스 스피커는 귀를 막지 않아 자기 소리를 마이크가 다시 들을 수 있습니다. 동반 앱은 OS의 통화용 에코 제거 경로로 녹음하는 것이 좋습니다(조사 문서, 기기 미검증).

## 4. 비용

버튼 방식보다 비쌉니다. 말이 없어도 소리가 계속 가고 사진이 3초마다 갑니다. 11/18 팀 검증 중 API 선불 크레딧이 소진될 만큼 썼습니다. 관람 1회 비용은 아직 재지 않았습니다(토큰 기록 장치를 다는 중). 줄이는 설정으로 `LIVE_FRAME_POLICY=on_speech`(말이 시작될 때 사진 한 장만)가 있습니다. 이 설정으로 작품 인식이 덜 되는지는 아직 재지 않았습니다.

## 5. 알려진 문제

| 문제 | 상태 |
| --- | --- |
| **답 하나가 통째로 다른(남성) 목소리로 나올 때가 있다** | 실기기에서 재현됐습니다. `gemini-3.8-live`의 알려진 문제로 Google 개발자 포럼에 보고돼 있고, Google 담당자가 "지금은 목소리를 고정하는 설정이 없다"고 답했습니다. 팀 합성 시험에서는 60턴 중 0번이었습니다. 대안 모델(`gemini-2.5-flash-native-audio-preview-12-2025`)은 팀 시험에서 30번 중 10번 답하지 않아 쓰지 않습니다 |
| **"음", "Yeah, I see" 같은 추임새에도 답할 때가 있다** | 지시문 규칙과 말 시작 민감도(LOW)로 일부 줄었습니다("Mm-hmm"은 3번 중 2번 조용함). 완전히 막지 못했습니다 |
| **제안만 한 비교도 요약에 기록된다** | 답 속에 비교 작품 제목이 나오면 기록하므로, 관람객이 거절해도 남습니다 |
| **작품 인식은 시연 11점 안에서만** | Live가 사진을 보고 11점 중에서 고릅니다. 실기기에서 씨름·서당·인왕제색도·초충도를 알아봤지만 정답표가 없어 정확도 숫자는 없습니다 |
| **새로고침되면 화면의 요약이 사라진다** | "Tap to continue your visit"로 같은 대화는 이어지지만, 화면의 본 작품 목록은 비어서 다시 시작합니다 |

## 6. 확인한 것과 확인하지 못한 것

**확인함(11/18)**: 실제 Gemini와 브라우저 자동화로 시작·질문·작품 인식·비교·화면 숨김/복귀·연결 끊김 후 대화 이음·요약·종료 6개 여정 통과, 끼어들기 2/2. 아이폰 실기기에서 인사·질문·인식·비교·끼어들기·화면 켜 둠·스피커 사용·20초 잠금 정상. 서버 자동 시험 99건, 화면 자동 시험 19가지 통과. 전달본과 같은 코드로 11/18 마지막에 다시 확인했습니다 — 인사 첫 음성 0.42초, 작품 인식 1.1초 뒤 `KHD_SSIREUM`, 비교 1.3초 뒤 `C_KHD_BRUEGEL`, 연결을 끊었다 다시 붙는 데 2.3초이고 앞 대화가 이어졌습니다.

**확인하지 못함**: 1분 넘는 잠금 뒤 재연결(실기기), 10분 넘는 연결, 실제 스마트글라스, 관람 1회 비용, `on_speech` 사진 정책의 인식률.
