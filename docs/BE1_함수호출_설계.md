# BE1: Live 함수 호출 설계 (`no_source`, 비교 기록)

작성: BE1 장인우 · 11/18

## 왜 필요한가

- 자료가 없어서 답을 못 한 질문을 모아 **콘텐츠 보강 목록**을 만든다. (FE1 관람분석 요청, `docs/meeting/요청_2026-11-16_관람분석.md`)
- AI가 실제로 설명한 비교를 폰에 알려서 **디자인 4번(비교 카드)과 5번(관람 요약)**을 채우고, 다음 작품에서 같은 비교를 **반복하지 않게** 한다. (`used_comparison_ids`)
- Live는 말(음성과 자막)만 돌려주고, **못 답했는지나 어떤 비교를 설명했는지는 따로 알려 주지 않는다.** 자막에서 글자를 찾는 방식은 AI가 표현을 바꾸면 놓치므로, AI가 말과 별도로 **신호(함수 호출)**를 보내게 한다. 관람객에게는 들리지 않아 말은 자연스럽게 유지된다.

## 함수 3개

| 함수 | 넣는 값 | 언제 부르나 |
| --- | --- | --- |
| `report_no_source` | `artwork_id`, `topic` (못 답한 내용, 영어 짧게) | 질문에 대한 답이 자료에 없을 때 |
| `report_out_of_scope` | `artwork_id`, `topic` | 시대로 넓혀도 답할 게 없거나 도슨트가 다룰 질문이 아닐 때 |
| `report_comparison` | `comparison_id` | 관람객에게 비교를 **실제로 설명했을 때** (제안만 했을 때는 부르지 않음) |

## `no_source` 판정 규칙

1. 질문에 대한 답이 자료에 없으면 부른다.
2. "기록에 없어요, 대신 이걸 보세요"처럼 **다른 정보를 대신 알려 줬어도** 부른다.
3. 질문에 여러 내용이 있으면 **못 답한 부분만, 부분마다 따로** 부른다.
   예) "누가 그렸고 정확히 몇 년도예요?" → 작가는 답함, `report_no_source(topic="exact date")` 한 번
4. 화가 개인으로는 답이 없지만 **시대로 넓히면 답할 수 있는 질문**(예: 화가가 좋아한 음식 → 조선 후기 음식 문화)은 `no_source`로 남긴다. 시대 배경 자료를 어디부터 채울지 정하는 근거로 쓴다.

## `out_of_scope` 예

가격, 개인 의견 요구("이 그림 좋아해요?"), 작품과 무관한 질문. 관람 규칙("사진 찍어도 돼요?")은 질문 유형 `navigation`으로 따로 본다.

## 역할

| 누구 | 할 일 |
| --- | --- |
| BE1 (인우) | 프롬프트에 "언제 부를지" 규칙 추가, 실제 대화로 자연스러운지 확인 |
| FE1 (도혁) | Live 설정에 함수 3개 등록, 신호를 받아 기록, `report_comparison`은 폰으로 전달 |
| FE2 (재호) | 서버가 보낸 `comparison_id`로 4번 카드, 5번 요약 띄우기 |
| FE3 (예원) | `no_source` 목록으로 자료 보강 |

## 저장 원칙

대화 원문은 저장하지 않는다. `artwork_id`, `topic`, `comparison_id`만 남긴다.
