# 60개 합성 음성 실험 복구와 추가 시험

2026-11-11 · FE1 · CPU·GPU·메모리 사용량은 사용자 요청에 따라 측정하지 않았다.

## 판단

Live의 수동 발화 경계에 무음 여유를 두는 방안을 유지할 근거를 얻었다. 다만 완료 신호 대기 시간 초과가 남아 있으며, 실제 아이폰 경로의 재시험 없이 정식 적용 효과를 확정하지 않는다. STT 서비스 및 TTS 음성의 최종 선택은 아직 미결정이다.

## 이전 세션 결과 복구

합성 화자 Samantha(en_US), Daniel(en_GB), Karen(en_AU), Moira(en_IE), Rishi(en_IN), Tessa(en_ZA)가 고정 영어 질문 10개를 읽었다. 실제 사람의 억양이나 현장 소음 시험이 아니다. 원본은 Claude 세션 `7e2bba28-de95-4f4b-8918-a584500a3e87`의 임시 폴더에 있다. 받아쓰기 원문과 음성을 저장소에 복사하지 않고 행별 점수만 `data/eval/voice_60_recovered.json`에 복구했다.

| 경로 | 완전 일치 | 단어 오류 | 받아쓰기 없음 | 기록된 시간 중앙값 |
| --- | --- | --- | --- | --- |
| Live 무음 없음 | 56/60 | 4/360 (1.11%) | 0 | 받아쓰기 시작 677.5ms |
| Live 앞뒤 300ms 무음 | 59/60 | 4/360 (1.11%) | 1 | 받아쓰기 시작 835ms (59건) |
| 기존 `/api/turn` | 60/60 | 0/360 (0%) | 0 | 전체 왕복 6,200ms |

무음 보정의 Daniel 5번은 빈 받아쓰기였다. 당시 결과 JSON에는 실패 종류가 없으므로 원인을 확정할 수 없다. 빈 결과의 정답 4단어가 오류 4개로 계산됐다. **완전 일치는 늘었지만 전체 단어 오류율은 같았다.**

이전 Live 스크립트는 음성을 실시간보다 빠르게 일괄 전송했고 첫 받아쓰기 조각까지를 쟀다. 기존 서버는 답변 생성까지 포함한 왕복을 쟀다. 두 수치로 STT 속도 배수를 계산하지 않는다. 모델·SDK 등의 이전 실행 설정은 결과 JSON 자체에 기록되지 않았으므로 당시 스크립트의 기본값만으로 실행 모델을 확정하지 않는다.

## 추가 STT 시험

도구: `experiments/voice/voice_boundary_experiment.py`. 결과: `data/eval/voice_boundary_2026-11-11.json`.

- 모델 `gemini-3.8-live`, google-genai `2.34.0`, Python `3.14.6`.
- 이전 오류 4문장과 무응답 1문장: Karen 7·8, Rishi 8, Tessa 5, Daniel 5.
- 각 문장을 조건별 5회, 합계 50회. 매 요청은 새 연결이며 반복마다 조건 순서를 반대로 했다.
- 자동 VAD를 끄고 `activity_start`·`activity_end`로 경계를 전달했다. 16kHz 모노 PCM16을 100ms 간격으로 실제 재생 속도에 맞춰 보냈고, 수신은 전송과 동시에 시작했다.
- 시스템 지시는 답을 `OK` 한 단어로 제한했다. 작품 문맥을 가진 도슨트 전체 경로나 별도 STT 모델 비교가 아니다.
- 무음 조건은 앞뒤 각 300ms를 **실시간 속도로** 보냈다. 현재 중계 스파이크의 무음 일괄 전송과 같지 않다.

| 조건 | 완전 일치 | 단어 오류 | 완료 대기 시간 초과 | 정상 완료 |
| --- | --- | --- | --- | --- |
| 무음 없음 | 10/25 | 15/170 (8.82%) | 1/25 | 24/25 |
| 앞뒤 300ms | 25/25 | 0/170 (0%) | 1/25 | 24/25 |

시간 초과 2건은 받아쓰기를 받았고 문장은 일치했으나 30초 내 턴 완료를 확인하지 못했다. 정확도 성공과 요청 완료 성공을 따로 센다. 이 결과를 일반 발화 전체의 정확도로 확대하지 않는다.

정상 완료 24건씩의 첫 받아쓰기 조각은 `activity_end` 직전 기준 중앙값 227.5ms(170–638)와 211.5ms(170–495), 첫 응답 음성 조각은 579ms(497–812)와 583ms(495–917)였다. 이때 응답은 `OK`이며 실제 기기 소리 재생 지연은 포함하지 않는다. 시간 초과 건의 시간은 집계에서 빠졌다. 무음 조건의 시간 기준은 뒤쪽 300ms 무음 이후이므로 마지막 실제 발화 이후 지연에는 300ms를 더해야 하고, 앞쪽 300ms도 입력 전체 길이를 늘린다. 이 수치로 두 조건의 체감 속도가 같다고 결론 내리지 않는다.

반복 결과의 일관성은 무음이 경계 단어 누락에 영향을 준다는 가설을 지지한다. CPU 프로파일링을 하지 않았으므로 성능 병목이나 속도 개선을 확정하지 않는다. 앞쪽·뒤쪽 무음 각각의 기여도도 분리하지 않았다.

## TTS 청취 시험

도구: `experiments/voice/voice_output_experiment.py`. 같은 Live 모델의 Kore·Puck·Aoede 음성을 각 5회 번갈아 호출했다. 독립 TTS 모델의 성능 비교는 아니다.

고정 대본에는 Kim Hong-do, Shin Yun-bok, Ssireum, Seodang을 단독으로 넣었다. 작품에 관한 사실 주장은 없다. 음성은 합성 시험 대본이며 관람객 음성·세션 기록은 포함하지 않는다. 첫 반복의 WAV만 임시 폴더 `/private/tmp/docent-voice-listening-20261111/`에 남긴다.

자막이 대본과 일치해도 실제 한국 인명·작품명 발음이 정확하다는 증거는 아니다. 발음·명료도·속도·선호는 직접 청취해서 평가해야 한다. 브라우저 TTS와의 동일 기기 비교 및 FE3 판정은 아직 하지 않았다.


| 음성 | 완료 | 대본 자막 일치 | 첫 음성 조각 중앙값 (범위) | 합성 길이 중앙값 |
| --- | --- | --- | --- | --- |
| Kore | 5/5 | 4/5 | 421ms (370–446) | 11.43초 |
| Puck | 5/5 | 3/5 | 456ms (373–530) | 12.96초 |
| Aoede | 5/5 | 4/5 | 480ms (432–524) | 10.48초 |

15건 모두 정상 완료했고 음성 바이트와 24kHz PCM MIME을 확인했다. 첫 조각 시간은 연결 완료 후 텍스트 전송 직전부터이며 연결 시간·기기 재생 지연을 제외한다. 음성 간 범위가 겹치고 병목을 분리 측정하지 않았으므로 속도 우열은 미확정이다. 결과는 `data/eval/voice_output_2026-11-11.json`에 남겼다. 대본 자막 불일치는 별도 기록했으며 음성 발음 오류로 곧바로 간주하지 않는다.

청취 샘플: [Kore](/private/tmp/docent-voice-listening-20261111/Kore.wav), [Puck](/private/tmp/docent-voice-listening-20261111/Puck.wav), [Aoede](/private/tmp/docent-voice-listening-20261111/Aoede.wav). 임시 폴더이므로 시스템 정리 시 사라질 수 있다.

## 사용자 실기기 시험 · 5G

사용자가 Live 시험 페이지에서 보고한 5회 결과다. 네트워크는 5G이며, 측정일은 2026-11-11 기록 기준이다. 기기 모델·OS 버전, 실제 질문과 작품, 실행 서버의 모델·SDK 버전은 이번 보고에서 별도로 확인하지 않았다.

| 회차 | 화면 시간 ms | 받아쓰기 정확 | 답변 들림 | 끊김·오류 |
| --- | --- | --- | --- | --- |
| 1 | 848 | 예 | 예 | 없음 |
| 2 | 1522 | 예 | 예 | 없음 |
| 3 | 804 | 예 | 예 | 없음 |
| 4 | 991 | 예 | 예 | 없음 |
| 5 | 749 | 예 | 예 | 없음 |

중앙값 848ms, 평균 982.8ms, 범위 749–1,522ms. 받아쓰기 정확·답변 청취 성공은 사용자 판정으로 각각 5/5이며 끊김·오류 보고는 0/5다. 첫 회도 집계에 포함했다.

화면 값은 버튼을 놓은 순간부터 첫 음성 데이터가 브라우저에 도착한 순간까지다. 실제 재생 예약·출력 지연은 제외하므로 귀에 들리기까지의 시간과 구분한다. 5회만으로 5G 전반의 안정성이나 다른 네트워크 대비 성능을 확정하지 않는다.

## 공식 근거

확인일 2026-11-11. 모델명·음성 설정·PCM 형식은 [Live 공식 가이드](https://ai.google.dev/gemini-api/docs/live-api/capabilities), SDK 버전은 [google-genai v2.34.0 공식 릴리스](https://github.com/googleapis/python-genai/releases/tag/v2.34.0)로 확인했다. 설치된 SDK 버전은 실행 결과에 기록했다. Live 음성 출력과 별도 TTS의 차이는 [공식 음성 생성 가이드](https://ai.google.dev/gemini-api/docs/speech-generation)를 참고한다.

## 남은 판단

1. 3종 샘플을 같은 이어폰·음량으로 듣고 한국 이름·작품명 발음, 명료도, 속도를 평가한다.
2. 아이폰 실제 입력에서 무음 전송과 단어 누락·지연을 함께 재확인한다.
3. 완료 신호 시간 초과를 별도 재현해 중계 화면이 대기 상태에 남지 않는지 확인한다.
4. 실제 사람 발화·현장 소음·브라우저 TTS 대조 시험 후 BE1·FE3와 최종 선택한다.
