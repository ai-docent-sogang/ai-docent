# 아이폰에서 현재 웹앱 시험하기

담당: FE1 김도혁. 상태: 시험 전. 최종 완성 전에도 현재 v0로 실행한다.

## 시험 준비하기

1. [README](../README.md)의 준비와 실행 절차로 서버를 켠다. `.env`와 의존성은 새 작업 폴더에도 별도로 준비한다. 키를 기록표에 적지 않는다.
2. Cloudflare 터널의 HTTPS 주소를 아이폰 Safari에서 연다.
3. 이어폰을 연결하고 음량과 무음 모드를 확인한다.
4. 맥 Safari의 개발자용 메뉴에서 연결된 아이폰의 페이지를 선택한다. 메뉴가 없으면 각 기기의 웹 검사 설정을 확인한다.
5. 아래 환경 기록을 채운다. 실제 관람객 대신 시험자와 사용 조건이 확인된 작품 자료를 쓴다.

## 텍스트 질문·답변(`/api/ask`)과 브라우저 음성 인식 시험하기

11/11에 추가한 흐름이다. 기존 P01~P10과 별개이며, Start를 누르지 않아도 쓸 수 있다(세션·카메라를 쓰지 않는다).
화면 아래 "Ask about one painting (text API)"를 펼쳐서 시험한다.

실제 Gemini 답변 없이 연결만 볼 때는 서버 `.env`에 `ASK_MOCK=1`을 넣고 서버를 다시 켠다.
답변 품질까지 볼 때는 `ASK_MOCK`을 지운다. 화면의 `status`로 어느 쪽인지 구분한다(`mock` / `ok`).

| ID | 동작 | 확인할 결과 | 결과·관찰 |
| --- | --- | --- | --- |
| A01 | 작품을 고르고 글로 "Who painted this?"를 보낸다 | 질문·답변 말풍선이 보이고 답이 음성으로 들린다. `status`, 서버 ms, total ms, 출처 링크가 보인다 | 미실행 |
| A02 | Speak question을 누르고 "Who painted this?"라고 말한다 | 말하는 중에 입력창에 흐린 글씨가 들어오고, 끝나면 또박또박한 질문이 남는다 | 미실행 |
| A03 | A02의 질문을 Ask로 보낸다 | 받아쓴 질문 그대로 답이 온다. 받아쓰기가 틀렸으면 틀린 내용을 적는다 | 미실행 |
| A04 | Speak question을 누른 뒤 아무 말 없이 기다린다 | "I did not catch that" 안내가 나오고 버튼이 되돌아온다 | 미실행 |
| A05 | 듣는 중에 Speak question을 다시 누른다 | 듣기가 멈추고 버튼이 되돌아온다 | 미실행 |
| A06 | 마이크 권한을 거부한 상태에서 Speak question을 누른다 | "Microphone blocked" 안내가 나오고 글 입력은 그대로 쓸 수 있다 | 미실행 |
| A07 | 답을 읽는 중에 Speak question을 누른다 | 읽기가 멈추고 듣기가 시작된다(마이크가 자기 목소리를 듣지 않아야 한다) | 미실행 |
| A08 | 기관 Wi-Fi 등 느린 망에서 A01을 반복한다 | 서버 ms와 total ms 차이를 적는다. 차이가 전송·대기 시간이다 | 미실행 |
| A09 | A01~A03 뒤에 기존 P01~P07을 해 본다 | 기존 녹음·사진 흐름이 그대로 동작한다(두 흐름이 서로 간섭하지 않아야 한다) | 미실행 |

브라우저 음성 인식에 대해 기록할 것:

- **소리가 기기 밖으로 나간다.** 아이폰 Safari는 Apple 서버, 크롬은 Google 서버로 보내 글자로 바꾼다.
  우리 서버를 거치지 않지만 외부 전송은 맞다. 시연 전에 팀과 이 점을 공유한다.
- 서버 받아쓰기(`/api/turn`의 Gemini)와 **같은 문장으로** 비교해 어느 쪽이 정확한지 [비교 기록표](FE1_음성_비교.md)에 적는다.
- 지원하지 않는 브라우저에서는 버튼이 꺼지고 "Type your question" 안내가 나온다. 기능이 사라지면 안 된다.

브라우저 없이 도는 검사(코드가 깨졌는지 먼저 확인할 때):

```
node tests/test_ask.mjs       # /api/ask 요청 형식
node tests/test_app_ask.mjs   # 질문·답변 화면 흐름
node tests/test_stt.mjs       # 음성 인식 처리
node tests/test_app_stt.mjs   # 음성 입력 버튼
```

## Live API 음성 왕복 시험하기 (전환 판단용)

[Live 검토](FE1_Live_검토.md)에서 맥으로는 확인했지만 아이폰에서 확인하지 못한 부분을 재는 항목이다.
**여기서 L02나 L03이 막히면 Live 전환은 성립하지 않는다.** 그래서 다른 작업보다 먼저 한다.

전용 시험 페이지를 쓴다. 운영 화면(`/`)과 별개이고 중계 스파이크 서버가 함께 내려준다.

```bash
uv sync --extra live                                                  # websockets 설치
PYTHONPATH=. uv run uvicorn --app-dir tools live_relay_spike:app --port 8013
cloudflared tunnel --url http://localhost:8013                        # 다른 터미널
```

출력된 `https://….trycloudflare.com/live` 를 아이폰 Safari에서 연다. 마이크는 HTTPS에서만 열린다.
이어폰을 쓴다(스피커로 하면 답변 소리를 마이크가 되받아 L06을 제대로 재기 어렵다).

| ID | 동작 | 확인할 결과 | 결과·관찰 |
| --- | --- | --- | --- |
| L01 | 페이지를 연다 | 맨 아래 줄에 "AudioWorklet 있음 · WebSocket 있음"이 보인다 | 미실행 |
| L02 | "연결하고 마이크 켜기"를 누르고 마이크를 허용한다 | 녹색으로 "재생 준비", "마이크 준비: ○○ Hz", "서버 준비"가 뜬다. 마이크 Hz 값을 적는다(보통 48000) | 미실행 |
| L03 | "시험음"을 누른다 | 440Hz 소리가 0.4초 들린다. **안 들리면 생 PCM 재생이 안 되는 것이므로 Live 전환 불가** | 미실행 |
| L04 | 빨간 버튼을 누른 채 "Who painted this?"라고 말하고 뗀다 | "들은 질문"에 받아쓴 글이 뜬다. 틀렸으면 틀린 내용을 적는다 | 미실행 |
| L05 | 그대로 기다린다 | 답변 음성이 들리고 "답변"에 글이 쌓인다. 중간에 끊기거나 튀는지 적는다 | 미실행 |
| L06 | 화면의 "말 끝난 뒤 첫 소리" 값을 적는다 | 맥 중계에서는 950~1,100 ms였다. 폰·기관 망에서의 값을 적는다 | 미실행 |
| L07 | 답변이 나오는 중에 빨간 버튼을 누른다 | 재생이 즉시 멈추고 다시 들을 준비가 된다 | 미실행 |
| L08 | 질문을 3~4번 이어서 한다 | 매번 답이 오고 연결이 유지된다. "WebSocket 닫힘"이 뜨면 code 값을 적는다 | 미실행 |
| L09 | 10분 넘게 열어 두고 다시 질문한다 | 연결 제한(약 10분)에 걸리는지 본다. 끊기면 code와 시점을 적는다 | 미실행 |
| L10 | 엉뚱한 작품을 골라 같은 질문을 한다 | 자료에 없다고 답한다(맥에서는 걸러냈다) | 미실행 |

기록할 값:

| 시험 ID | 마이크 Hz | 재생 Hz | 말 끝난 뒤 첫 소리 ms | 받아쓰기 정확 | 끊김·오류 |
| --- | --- | --- | --- | --- | --- |
| 미기록 | 미기록 | 미기록 | 미측정 | 미기록 | 미기록 |

막혔을 때 볼 곳:

- "AudioWorklet 없음" → iOS 버전을 적는다. 이 경로는 쓸 수 없다.
- L03 무음 → 음량·무음 모드·이어폰을 확인한 뒤에도 안 들리면 재생 경로 문제다. 화면의 "재생 Hz"를 적는다.
- "WebSocket 닫힘 (code 1006)" → 터널이나 망 문제일 수 있다. 같은 Wi-Fi에서 다시 해 본다.
- 받아쓰기가 비어 있음 → 마이크 권한은 허용됐는데 소리가 안 가는 경우다. 화면의 "보냄 KB"가 0인지 본다.

## 지연과 오류 기록하기

- 현재 화면의 total은 전송 시작부터 응답 수신까지다. 녹음 변환과 실제 음성 재생 시작은 포함하지 않는다.
- 체감 지연은 버튼에서 손을 뗀 순간부터 답의 첫 소리가 들린 순간까지로 기록한다. 녹음 종료 자동 감지가 붙으면 시작 기준을 다시 명시한다.
- 스톱워치로 재면 수동 측정이라고 표시한다. 현재 측정 도구가 없으면 미측정으로 남긴다.
- 시험 ID, 재현 순서, 예상 결과, 실제 결과, 정제한 오류 메시지를 남긴다. 키, 대화 원문, 음성, 프레임은 저장하지 않는다.
- 같은 조건으로 다시 시험할 때는 새 세션을 시작한다. 현재 웹앱에는 종료 기능이 없으므로 서버 재시작으로 기존 세션을 폐기하고 페이지를 새로 연다.

| 시험 ID | 체감 지연 ms | 측정 방법 | 화면 Gemini ms | 화면 total ms | 오류·재현 조건 |
| --- | --- | --- | --- | --- | --- |
| 미기록 | 미측정 | 미기록 | 미측정 | 미측정 | 미기록 |

가리키기와 여러 프레임 전송은 현재 미구현이다. FE2와 BE1 연동 후 시험 항목을 추가한다. STT·TTS 선택은 [비교 기록표](FE1_음성_비교.md)를 사용한다.
