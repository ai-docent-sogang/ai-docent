# 운영 페이지와 질문 라벨 — 변경 안내 (11/19)

작성: FE1 김도혁(팀장). 브랜치 `dohyeok/ops-page`. 근거: [결정 사항](../결정사항.md) 11/19, [api.md](../api.md) 운영 API, [관람기록 설계](../FE1/관람기록_설계.md).

## 1. 한 장 요약

- **운영 페이지 `/admin`을 만들었습니다.** 대시보드, 질문 라벨, 작품 켜기/끄기 세 탭입니다. 계획서 45줄이 12/1 범위에 넣었는데 코드가 0줄이었습니다.
- **일정상 FE1이 세 가지를 모두 구현했습니다.** 원래 화면은 FE2, 집계·켜기/끄기 API는 BE1 몫입니다(역할 가이드 202·216·231줄). 남의 파일을 가져간 것이 아니라 **새 파일로 만들었고**, `server/app.py`에는 3줄만 더했습니다.
- **Live가 질문 유형과 답 결과를 함수 호출로 보고하게 했습니다.** 그래야 "작품 × 질문 라벨 × 결과" 지도를 만들 수 있습니다.
- **새 규칙: Gemini 모델 ID도 `.env`에서 관리합니다.** 코드에 모델 이름을 박지 않습니다.
- **운영 페이지에는 인증이 없습니다.** localhost에서만 엽니다. 터널을 열어 둔 동안에는 쓰지 않습니다.

## 2. 새로 생긴 주소

| 주소 | 하는 일 |
| --- | --- |
| `GET /admin` | 운영 화면(세 탭) |
| `GET /api/admin/stats` | 관람 기록 집계. 기간과 `source_kind`를 쿼리로 받습니다 |
| `GET /api/admin/artworks` | 작품 목록과 켜짐·꺼짐 |

형식은 [api.md](../api.md)의 "운영 API" 절에 있습니다. 관람객 경로(`/`, `/api/turn`, `/api/ask`, `/ws/live`)는 **바뀌지 않았습니다.**

새 파일: `server/admin.py`, `server/visit_stats.py`(집계 수식), `server/on_view.py`(켜기/끄기 상태), `server/question_labels.py`(라벨 단일 출처), `static/admin.html`, `static/admin.js`.

## 3. 담당별로 확인해 주실 것

### BE1 인우님

1. **`server/app.py`에 3줄을 더했습니다.** import, `admin_api.artworks` 주입, `include_router`입니다. 기존 주입 관례를 그대로 따랐습니다. 봐 주시고 다른 모양이 좋으면 알려 주세요.
2. **`no_source` 판정 방식을 바꿨습니다.** [관람기록 설계](../FE1/관람기록_설계.md)에는 "지시문에 정해진 문장을 넣고 서버가 그 문장을 찾는다"로 적혀 있었고 담당이 BE1이었습니다. 지금은 **Live가 `report_question` 함수로 직접 보고**합니다. 값은 `answered`, `no_source`, `out_of_scope`, `unknown` 네 개입니다. 지시문 쪽에서 다르게 하려던 계획이 있으면 맞춰야 합니다.
3. **`server/ask.py:57`의 `DEFAULT_FALLBACK_MODELS`에 모델 이름이 박혀 있습니다.** 새 `.env` 규칙과 어긋납니다. BE1 파일이라 제가 고치지 않았습니다.
4. 지시문에 두 줄을 더했습니다(`server/live_config.py`의 `handsfree_instruction`). "질문마다 답하기 전에 `report_question`을 부른다"와 "라벨을 소리 내어 읽지 않는다"입니다.

### FE2 재호님

1. **운영 화면을 FE1이 만들었습니다.** `static/admin.html`과 `static/admin.js`입니다. 역할 가이드에 FE2 몫으로 적혀 있던 파일 이름을 그대로 썼습니다. 이어받으시려면 그대로 쓰시고, 모양을 다시 잡으셔도 됩니다.
2. **`static/index.html`과 `static/style.css`는 건드리지 않았습니다.** 운영 화면은 `style.css`를 불러오지 않고 자체 스타일만 씁니다. 관람객 화면과 섞이지 않습니다.
3. `static/admin.js`는 `document`가 없으면 DOM 부분을 건너뛰도록 짰습니다. 그래서 순수 함수만 `tests/test_admin_view.mjs`로 시험합니다.

### FE3 예원님

1. **질문 라벨 10개를 그대로 확정했습니다.** `fact`, `artist`, `meaning`, `context`, `technique`, `comparison`, `navigation`, `request`, `other`, `unknown`입니다.
2. **정의를 `server/question_labels.py` 한 곳으로 옮겼습니다.** `tools/classify_questions.py`가 거기서 가져다 씁니다. 평가 질문의 `label` 칸과 **같은 체계**이므로, 라벨 정의를 고치실 때는 그 파일 하나만 고치면 분류기와 Live가 함께 따라옵니다.
3. 관람 중 라벨은 Live가 보고하고, 관람 뒤 분류는 기존 도구가 합니다. 두 값을 견주려면 정의가 하나여야 해서 이렇게 했습니다.

### BE2 준환님

2. **`data/incoming/exhibit_11/reference/`의 두 파일이 `.gitignore`가 막는 경로에 올라가 있습니다.** `demo_manifest.csv`와 `index_demo.npz`(32KB 바이너리)입니다. GitHub 웹 업로드가 `.gitignore`를 거치지 않습니다. 일부러 두시려면 `.gitignore`에 예외를 적고, 아니면 추적을 푸는 게 좋습니다.
3. **인식기가 Live에 붙을 때는 후보 목록을 만드는 자리에서 `on_view.visible()`을 지나게** 해 주세요. CSV를 읽는 시점에 거르면 운영 페이지의 켜기/끄기가 반영되지 않습니다. `server/on_view.py` 머리에 적어 두었습니다.

## 4. 새 규칙 — 모델 ID는 `.env`에서

[AGENTS.md](../../AGENTS.md)에 한 줄 더했습니다.

> Gemini 모델 ID도 `.env`에서 관리한다. 코드에 모델 이름을 박지 않는다. 쓰는 값은 `GEMINI_MODEL`, `LIVE_MODEL`, `ASK_FALLBACK_MODELS`다.

모델을 바꿀 때 코드를 고치지 않아도 되게 하고, 어느 모델로 측정했는지 `.env` 하나만 보면 알게 하기 위함입니다. 11/4 시연에서 어떤 모델을 썼는지 아무 데도 남지 않은 일이 있었습니다.

규칙과 어긋나는 자리가 지금 다섯 곳 있습니다. 담당자가 정해 주세요.

| 파일 | 박혀 있는 값 | 담당 |
| --- | --- | --- |
| `server/live_config.py:43` | `LIVE_MODEL` 기본값 `gemini-3.8-live` | FE1 |
| `server/ask.py:57` | `DEFAULT_FALLBACK_MODELS` 세 개 | BE1 |
| `tools/classify_questions.py:47` | `GEMINI_MODEL` 기본값 `gemini-3.8-flash` | FE3·FE1 |
| `tools/live_frame_recognition.py:47` | `LIVE_MODEL` 기본값 | FE1 |
| `tools/compare_modes.py:42` | `LIVE_MODEL_CANDIDATES` 세 개 | BE1 |

기본값을 지우면 `.env`가 없을 때 서버가 바로 멈춥니다. 그게 규칙에 맞지만 동작이 바뀌므로 각자 파일에서 정해 주세요.

## 5. 아직 안 된 것

- **실제 Gemini로 재지 않았습니다.** 라벨이 정말 들어오는지와 `report_question`이 늘린 지연입니다. 설계 문서에 **함수 호출 방식은 첫 음성이 0.4~2.5초 늦어진 측정(T1, 11/18)** 이 적혀 있습니다. 재서 나빠지면 "답한 뒤 호출"로 바꿉니다.
- **실기기 확인이 남았습니다.** 작품을 끄고 Live를 다시 붙여 후보에서 빠지는지입니다. 브라우저로는 화면과 API까지만 봤습니다.
- **`docs/api.md`에 `/ws/live` 절이 없습니다.** 11/18에 쓴 문서 묶음(PR #26)을 올리지 않기로 해서, Live가 main에 들어왔는데 주고받는 형식이 문서에 없는 상태입니다. 기기를 붙이려면 이 절이 필요합니다.

## 6. 쓸 때 주의할 것 셋

1. **`visit`은 사람이 아니라 폰 연결 1회입니다.** 재연결하면 한 사람의 관람이 두 건으로 세어집니다. 화면에 같이 띄워 두었고 `quality.reconnect` 건수로 눈치챌 수 있습니다.
2. **작품별 "인식 구간"은 체류 시간이 아닙니다.** 특정 작품 인식부터 다른 작품 인식까지입니다. 카메라를 내리고 가만히 들은 시간이 앞 작품에 붙습니다.
3. **첫 소리까지 걸린 시간은 관람객이 기다린 시간보다 약 1초 작습니다.** 턴 사이를 견주는 데는 쓸 수 있지만 "몇 초 기다렸다"로 말하면 안 됩니다.
