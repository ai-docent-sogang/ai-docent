- **MVP 범위는 회의록 그대로입니다.** (1) 작품 인식·해설 (2) Gemini Live API 대화. 늘리지 않습니다.

## 2. 왜 11/17 오전인가

11/18 오전에 멘토에게 전달하려면 통합·리허설·재녹화 여유가 반나절밖에 없습니다. "11/18까지"로 두면 18일 아침에 도착해서 못 붙입니다. 11/17 오전에 받으면 그날 하루를 통합에 씁니다.

아직 안 끝난 상태로 주셔도 됩니다. **붙는 모양만 3번 표의 형식에 맞으면** 내용이 미완성이어도 통합할 수 있습니다.

## 4. BE1(인우)과 나눌 경계 — 먼저 확인 부탁합니다

Live 전환이 회의에서 확정됐는데, Live 적용 작업이 두 사람에게 걸쳐 있습니다. 이렇게 나누면 지금 만들어 둔 것을 그대로 쓸 수 있습니다.

| 영역 | 담당 | 현재 상태 |
| --- | --- | --- |
| 폰 마이크 → 16kHz PCM 실시간 전송 | FE1 | 아이폰 Safari에서 동작 확인 (`static/live_mic_worklet.js`) |
| 24kHz PCM 받아서 끊김 없이 재생 | FE1 | 동작 확인 (`static/live_player.js`) |
| 폰 ↔ 서버 ↔ Gemini WebSocket 중계 | FE1 | 스파이크 동작 (`tools/live_relay_spike.py`). 서버 정식 반영은 BE1과 합의 후 |
| 끊김 재연결·세션 수명 | FE1 | 2분 비활성 종료는 처리. 10분·15분 제한은 미확인 |
| 시스템 지시문·작품 맥락·개인화 프롬프트 | BE1 | `server/prompts.py`, `server/ask.py` |
| 대화 품질·사실 정확도 | BE1 | — |
| 여러 관람객 동시 접속·인증 | — | **11/18 범위 밖으로 정했습니다**(11/13). 1명 시연. 12/1 범위로 미룹니다 |

중계 스파이크는 `tools/`에 있고 운영 서버(`server/app.py`)를 건드리지 않았습니다. 정식으로 넣는 위치와 방법은 인우님 의견을 듣고 정하겠습니다.

## 5. 인식이 약할 때의 대비 — 전달본은 직접 선택을 기본으로

회의에서 BE2 인식이 테스트 23장 중 약 4장 정답으로 보고됐습니다. 11/17까지 크게 오르지 않을 수 있어서, **멘토 전달본은 작품을 목록에서 직접 고르는 경로를 기본**으로 두겠습니다. 인식은 되는 범위에서 함께 보여줍니다.

개발계획서에 원래 "인식 실패 시 목록에서 직접 고른다"가 대체 경로로 들어 있어서 새로 만드는 것이 아닙니다. 이렇게 하면 인식 정확도와 무관하게 Live 대화 품질은 온전히 전달됩니다.

BE2(준환)는 인식 개선 실험을 계속하시고, **11/17에 정확도 숫자만 알려 주세요.** 그 숫자로 전달본에서 인식을 어디까지 보여줄지 정합니다.

**합격 기준(11/13 결정): 시연 작품 11점만 대상으로 Top-1 70%.** 이 숫자를 넘으면 전달본에서 인식 경로를 함께 보여주고, 못 넘으면 전달본에서는 직접 선택만 두고 인식은 11/18 회의에서 실험 결과로 공유합니다. 전체 DB(1,100~1,300건) 기준이 아니라 11점 한정 기준입니다. 회의에서 11점 제한과 전체 DB의 성능 차이가 크다고 보고됐고, 전달본이 11점 시연이므로 기준도 같은 조건에 맞췄습니다.

- 박물관: 전시품 목록, 11점 실제 전시 여부, 촬영·시연 허가 (회신 대기가 있어 먼저 보냅니다)
- 멘토: 임베딩 모델 지원 시점 문의 (BE2 작업의 전제)

기관용 데이터 수집 구조와 외국인 테스터 섭외는 11/18 이후로 미룹니다.

## 7. 11/13에 정한 것 (팀장 결정)

회의록에 "미정"으로 남았던 것 중 팀장이 단독으로 정할 수 있는 네 가지를 정했습니다. 바꿔야 할 이유가 있으면 11/18 회의에서 말씀해 주세요.

| 항목 | 정한 것 | 이유 |
| --- | --- | --- |
| 인식 합격 기준 | **11점 한정 Top-1 70%** | 전달본이 11점 시연이라 기준도 같은 조건. BE2가 멈출 지점이 생깁니다 (5번 참고) |
| 여러 관람객 동시 접속·인증 | **11/18 범위 밖.** 1명 시연만 | 멘토 1명이 테스트하는 전달본입니다. 동시 접속·인증은 12/1 시연 범위로 미룹니다 |
| 스마트글라스 설명 | **폰 웹으로 먼저 검증하고, 글라스는 같은 API에 붙는 출력 장치로 설명** | 개발계획서가 이미 그렇게 두고 있습니다(3·64줄). 대화·인식 품질 검증을 기기 입수 시점에 종속시키지 않습니다 |
| Live 음성(Kore·Puck·Aoede) | **아직 미정.** 청취 평가 먼저 | 자막 일치·응답 시간은 세 음성이 겹칩니다. 한국 인명·작품명 발음은 들어봐야 판정됩니다 |

음성은 기한을 둡니다. **11/16(일)까지 3종을 같은 이어폰·음량으로 듣고 정하고, 그때까지 못 정하면 Kore를 전달본 기본값으로 씁니다.** Kore가 첫 음성 조각 중앙값 421ms로 가장 빠르고 대본 자막 일치도 4/5입니다. 전달본에 기본값이 비어 있는 상태를 만들지 않기 위한 보험이고, 청취 결과가 다르면 바꿉니다.
