# 11/18 전달본 통합 인터페이스 — 초안

작성: FE1 김도혁, 2026-11-12. 상태: **초안. BE1 합의 전.**

## 이 문서의 위치

[`docs/api.md`](api.md)는 BE1이 관리하고, 바꿀 때 BE1과 FE1이 함께 리뷰합니다. Live 전환은 `api.md` 마지막 줄에 "이 문서 전체를 새로 쓴다"로 적혀 있는 큰 변경이라, 합의 전에 `api.md`를 고치지 않고 여기에 먼저 적습니다.

**BE1(인우)이 확인하면 이 내용을 `api.md`에 옮기고 이 파일은 지웁니다.**

범위는 11/18 멘토 전달본에 필요한 것까지입니다. 12/1 시연용 전체 설계가 아닙니다.

## 왜 형식을 먼저 고정하나

11/11 회의에서 각자 실험을 병행하기로 했습니다. 실험 내용은 자유롭게 하되 **바깥으로 내보내는 형식만 맞으면** 따로 작업해도 11/17에 붙습니다. 아래 네 군데가 접점입니다.

```text
[폰] 초기 설정(FE2) → 작품 선택 또는 인식(BE2) → Live 음성 대화(FE1 중계 + BE1 지시문)
                                                      ↑
                                            작품 사실 CSV(FE3)
```

## 1. 음성 중계 — 폰 ↔ 서버 ↔ Gemini Live (FE1)

현재 `tools/live_relay_spike.py`에서 동작하는 형식입니다. 아이폰 Safari에서 왕복 확인했습니다(L01~L10 통과, 말 끝난 뒤 첫 소리 1,457 ms).

WebSocket 주소: `/ws/live` (운영 서버의 어느 경로에 둘지는 BE1과 정합니다)

### 폰 → 서버

| 순서 | 보내는 것 | 형식 |
| --- | --- | --- |
| 연결 직후 1회 | 어느 작품인지 | 텍스트 `{"artwork_id": "KHD_SSIREUM"}` |
| 버튼 누름 | 말 시작 | 텍스트 `{"type": "speech_start"}` |
| 누르고 있는 동안 | 마이크 소리 | 바이너리, 16kHz 모노 PCM16 |
| 버튼 뗌 | 말 끝 | 텍스트 `{"type": "speech_end"}` |

### 서버 → 폰

| 받는 것 | 형식 | 폰이 할 일 |
| --- | --- | --- |
| 준비됨 | `{"type": "ready", "model": "...", "artwork_title": "..."}` | 버튼 활성화 |
| 받아쓴 질문 | `{"type": "heard", "text": "..."}` | 화면에 질문 표시 |
| 답변 음성 | 바이너리, 24kHz 모노 PCM16 | 이어 붙여 재생 |
| 답변 자막 | `{"type": "said", "text": "..."}` | 화면에 답 표시 |
| 턴 끝 | `{"type": "turn_complete"}` | 버튼 다시 활성화 |
| 재연결 중 | `{"type": "reconnecting"}` | "잠시만요" 안내, 버튼 잠금 |
| 다시 붙음 | `{"type": "reconnected", ...}` | 버튼 활성화. 대화 내용은 유지됨 |
| 오류 | `{"type": "error", "message": "..."}` | 안내 문구 표시 |

### 구현에서 주의할 것 (실기기에서 겪은 것)

- **자동 음성 감지(VAD)를 끄고** `activity_start`·`activity_end`로 경계를 알립니다. 버튼을 누르는 동안만 소리를 보내므로 모델에 침묵이 전달되지 않아 말의 끝을 알 수 없습니다. 섞어 쓰면 첫 턴만 동작합니다.
- **말의 앞뒤에 300ms 무음**을 넣습니다. 경계에 말이 바로 붙으면 첫 단어·끝 단어가 잘립니다. 11/11 측정에서 취약 문장 5개를 조건별 5회(각 25건) 시험해 완전 일치가 10/25 → 25/25였습니다. 실제 아이폰 중계 경로에서의 재확인은 아직 하지 않았습니다.
- **`session.receive()`는 한 턴이 끝나면 스스로 끝납니다.** 턴마다 다시 불러야 합니다. 한 번만 돌리면 두 번째 질문부터 답이 오지 않고, 아무도 Gemini 소켓을 읽지 않아 연결이 끊깁니다.
- **질문 사이 2분이면 Gemini가 세션을 닫습니다**(`1008 client inactivity`, 폰에는 1006으로 보임). `session_resumption` 핸들로 다시 붙으면 대화 내용이 유지됩니다.
- **Gemini 읽기와 폰 보내기를 큐로 떼어 놓습니다.** 붙여 두면 폰이 느릴 때 Gemini 연결이 keepalive ping timeout으로 끊깁니다.
- **아직 없는 것**: 음성 전용 세션 15분·연결 약 10분 제한 처리(`GoAway`, `contextWindowCompression`), 작품 변경, 에코 처리.
- **여러 관람객 동시 접속과 인증은 11/18 범위 밖입니다**(11/13 팀장 결정). 멘토 1명이 테스트하는 전달본이라 단일 세션으로 둡니다. 12/1 시연 범위로 미룹니다. 전달본 시연 중에는 **한 번에 한 명만 접속**하면 됩니다.

## 2. 작품 인식 (BE2)

인식 방식(YOLO·DINOv2·임곗값)은 BE2가 자유롭게 실험합니다. 통합에 필요한 것은 **내보내는 모양**뿐입니다.

입력: 사진 한 장(JPEG). 출력:

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `artwork_id` | 문자열 | `data/artworks.csv`의 ID. 확실하지 않으면 `"unknown"` |
| `score` | 숫자 | 0~1. 확신 정도 |
| `candidates` | 배열(선택) | `[{"artwork_id": "...", "score": 0.0}]` 상위 후보. 없어도 됩니다 |

함수 호출로 받을지 HTTP로 받을지는 11/17까지 정합니다. 11/18 전달본은 **목록에서 직접 고르는 경로를 기본**으로 두므로, 인식이 미완성이어도 통합은 진행됩니다.

`unknown`을 돌려주는 것이 틀린 ID를 돌려주는 것보다 낫습니다. 작품을 잘못 알아보면 그 뒤 설명이 전부 틀린 설명이 됩니다.

## 3. 대화 내용 — 시스템 지시문과 작품 맥락 (BE1)

Live 세션을 열 때 시스템 지시문에 작품 맥락을 넣습니다. 현재 스파이크는 기존 코드를 그대로 씁니다.

```python
system_instruction = f"{ASK_INSTRUCTION}\n\n{build_artwork_context(art)}"
```

- `ASK_INSTRUCTION`: `server/prompts.py`
- `build_artwork_context()`: `server/ask.py`

이 방식으로 Live가 `key_facts` 안에서만 답하고, 자료에 없는 질문(다른 작품에 대고 물은 경우)은 지어내지 않고 걸러내는 것을 확인했습니다. BE1이 측정한 사실 정확도 10/0/0도 같은 방식이었습니다.

개인화(국적·연령대·언어에 따른 어조·속도)를 지시문에 어떻게 넣을지는 BE1이 설계합니다. 중계 쪽은 **지시문 문자열을 받아 그대로 넣기만** 하므로, 지시문이 길어지거나 바뀌어도 중계 코드는 고치지 않습니다.

프로필을 세션 중간에 바꿔야 하면 알려 주세요. 지금은 연결할 때 한 번만 넣습니다.

## 4. 작품 사실 CSV (FE3)

`data/artworks.csv`에서 통합이 읽는 컬럼입니다. **이 컬럼명을 바꾸면 서버가 죽습니다.**

| 컬럼 | 쓰는 곳 |
| --- | --- |
| `artwork_id` | 인식 결과, 작품 선택, Live 연결 첫 메시지 |
| `title_en` | 화면 표시, `ready` 메시지 |
| `key_facts` | 시스템 지시문 (영어) |
| `source_notes` | 시스템 지시문 (운영 메모. 회의에서 당분간 이 컬럼에 두기로 함) |
| `source_url` | 출처 링크 표시 |
| `verification_status` | 검증 상태 |

내용을 늘리고 고치는 것은 자유입니다. 컬럼을 추가하는 것도 괜찮습니다. **없애거나 이름을 바꿀 때만** 미리 알려 주세요.

Excel로 저장하면 파일 앞에 보이지 않는 글자(BOM)가 붙어서 전에 서버가 죽은 적이 있습니다. 지금은 `server/content.py`가 `utf-8-sig`로 읽어서 괜찮습니다.

## 5. 초기 설정값 (FE2)

세션을 시작할 때 폰이 보내는 값입니다. 회의에서 국적·연령대까지 합의했고 그 밖은 미정입니다.

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `country` | 문자열 | 국적 |
| `age_group` | 문자열 | 연령대 |
| `language` | 문자열 | 언어. 11/18 전달본은 `"en"` |

입력 방식(선택형 vs 음성)은 회의에서 UI 단계에 맡기기로 했습니다. **어느 쪽이든 서버로 가는 값은 위 세 개로 같습니다.**
