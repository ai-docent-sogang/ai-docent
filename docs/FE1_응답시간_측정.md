# `/api/ask` 응답 시간 측정 (FE1, 2026-11-11)

담당: FE1 김도혁. 측정 데이터: [`data/eval/ask_latency.csv`](../data/eval/ask_latency.csv).

## 왜 측정했나

11/9 시연 보고의 "체감 6~7초"는 스톱워치 수동 추정이었고 표본 수와 측정 구간이 없었다. 어디가 느린지
모르면 고칠 수도 없다. BE1이 11/11에 추가한 `/api/ask`는 응답에 `latency_ms`를 담아 주므로 서버 안에서
걸린 시간과 왕복 시간을 나눠 볼 수 있게 되었다.

## 어떻게 측정했나

- 질문: BE1의 방식 비교와 **같은 10개**(`data/eval/mode_comparison.csv`의 Q01~Q10). 비교 가능하게 하려고 같은 세트를 썼다.
- 경로: 로컬 서버 `POST /api/ask`, 실제 Gemini 호출(`ASK_MOCK` 없음), `.env`의 `GEMINI_MODEL` = `gemini-3.8-flash`.
- `server_ms`: 서버가 응답에 담아 준 `latency_ms`(요청을 받고 답변을 만들기까지).
- `client_ms`: 요청을 보낸 쪽에서 잰 왕복 시간.
- 같은 기계에서 쟀다. **네트워크 구간이 거의 0이다.** 폰·외부 서버에서는 더 걸린다.
- 10회 1회씩. 재시도·평균 반복은 하지 않았다.

## 결과

| 항목 | 값 |
| --- | --- |
| 성공 | 10 / 10 (모두 `status: ok`) |
| 서버 시간 중앙값 | 7,945 ms |
| 서버 시간 최소 / 최대 | 5,936 ms / 9,397 ms |
| 왕복 − 서버 시간 | 2~15 ms |

## 읽은 것

**느린 곳은 Gemini다.** 왕복 시간과 서버 시간의 차이가 15ms 이하다. 우리 코드, 전송량, 서버 처리는
사실상 시간을 쓰지 않는다. 약 8초는 모델이 답을 만드는 시간이다.

**텍스트 전용이라서 빨라지지는 않았다.** `server/ask.py`의 머리말은 "보내는 양이 적어 `/api/turn`보다
빠를 것으로 기대한다"고 적어 두었다. 같은 질문 기준으로 BE1이 측정한 요청-응답 방식이 8.1초, 이번
`/api/ask`가 7.9초다. 차이가 거의 없다. 사진·음성을 빼도 모델의 생각 시간이 그대로 남기 때문이다.
보내는 양을 줄이는 방향으로는 이 8초를 줄일 수 없다.

**관람객이 느끼는 시간은 이보다 길다.** 이 숫자에는 브라우저 음성 인식(말이 끝났다고 판단하는 시간),
폰↔서버 네트워크, 답변을 소리 내기 시작하는 시간이 빠져 있다. 11/9의 체감 6~7초가 이 8초보다 짧은 것은
측정 구간이 달랐기 때문으로 보인다(수동 추정이라 단정하지 않는다).

## 답변 내용

자료에 없는 질문 3개를 섞어 두었는데 모두 모른다고 답했다. 지어내지 않았다.

- Q03 "How much is this painting worth?" → 가격 자료가 없다고 답하고 다른 볼거리를 권했다.
- Q06 "How big is this painting?" → 정확한 크기를 모른다고 답했다. (`artworks.csv`에 크기 열이 없다.)
- Q08 "What was the painter's favorite food?" → 기록에 없다고 답했다.
- Q04 "Why is the boy crying?"의 회초리·암송 평가 해석은 `key_facts`에 출처(국사편찬위원회)와 함께 들어
  있는 내용이고, 답변도 "이 아이의 기록은 아니다"라는 단서를 함께 말했다. 자료 범위를 벗어나지 않았다.

이 채점은 FE1의 1차 확인이다. 사실 검증은 FE3·BE1이 맡는다.
